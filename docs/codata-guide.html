Codata 使用与配置文档

Codata 是一个本地优先的桌面 Data Agent:你用自然语言提出数据问题,它替你发现表和指标口径、生成或复用 SQL、执行查询,再把结果整理成结果卡片和图表,并支持把有价值的分析钉到看板,或交给专家团做深度分析。对话、看板、记忆和生成产物默认存储在本机,只有在你选择云端模型或外部连接器时,相关上下文才会发送给对应服务。

它主要面向需要频繁问数、取数和做分析的分析师与业务团队。你不用先记住表在哪、字段怎么拼、口径怎么算——用业务语言把问题说清楚,由 Agent 完成 schema 检查、指标检索、SQL 生成与纠错,并用具体数字、口径说明和 SQL 解释结论,让你能核对答案从哪里来。

一句话理解 Codata 的分析闭环 自然语言问数 → 发现表 / 字段 / 指标口径 → 生成或复用 SQL → 执行查询 → 查看结果卡片、SQL 与图表 → 钉到看板,或交给专家团做深度分析。

自然语言查数

用业务语言描述问题,Codata 转成完整分析流程:schema 检查、指标检索、SQL 生成、执行查询与结论解释。

SQL 与结果可检查

结果不藏在文字后面。查询结果、SQL、字段、行数据和图表元数据都会保留,方便核对答案来源。

看板与专家团

把图表结果钉到命名看板,支持刷新;复杂问题可交给多 Agent 专家团拆分成发现、SQL、归因、可视化与报告。

安装

Codata 是桌面应用,从公司统一的 站点下载页 下载对应平台安装包即可。目前提供 Windows 与 macOS 两个平台,安装后应用会随本机一起运行,无需额外部署后端。

平台 架构 安装包
Windows x86_64(64 位) NSIS 安装程序 .exe
macOS(Apple Silicon) aarch64(M 系列芯片) .dmg
macOS(Intel) x86_64 .dmg

Windows 安装

下载安装程序

在站点下载页选择 Windows 版本,下载 .exe 安装程序。

运行并按向导安装

双击运行,按 NSIS 安装向导选择安装位置并完成安装。

启动应用

从开始菜单或桌面快捷方式启动,桌面端会随应用一起运行本机后端服务。

macOS 安装

选择正确的架构

M 系列芯片(Apple Silicon)选 aarch64 版本,较旧的 Intel 机型选 x86_64 版本。不确定时,可在「关于本机」中查看芯片型号。

打开 DMG 并拖入应用程序

双击 .dmg,把 Codata 拖到「应用程序」文件夹。

首次启动

从启动台或应用程序文件夹打开 Codata。

macOS 首次启动说明 发布的 macOS 安装包经过 Apple 签名与公证,正常情况下双击即可打开。如果系统仍弹出 Gatekeeper 提示,右键点击应用图标 → 选择「打开」,在确认框中再次点「打开」即可。系统最低要求为 macOS 10.15。

配置详解

本章讲清楚三件让 Codata 真正跑起来的事:接入模型、接入数据与工具(MCP)、以及用权限控制 Agent 能做什么。首次使用请至少完成「模型来源与 API Key」,再按需要接入 datasage 数据平台。

模型来源与 API Key

模型来源在 设置 →「模型」标签里配置。支持两类来源:填入 API Key 的云端供应商(如 Anthropic、OpenAI 或兼容 OpenAI 的服务),以及运行在本机的 Ollama 本地模型。你可以同时连接多个来源,并随时在会话里切换。

首次使用必做 发起第一个问题之前,必须先在这里连接至少一个可用模型;否则问答首页的模型下拉里没有可选项,查询无法开始。
打开设置 → 模型

从左侧会话栏进入设置,选择「模型」标签(模型来源、API Key 和默认模型都在这里管理)。

选择供应商并填写 API Key

添加一个云端供应商,填入对应的 API Key。想用本机模型时,改为配置本地 Ollama(将 Codata 指向本地 OpenAI 兼容端点,例如 http://localhost:11434/v1)。

保存并确认可用

保存后来源显示为「已就绪」,其模型会出现在问答首页的模型下拉中。可在设置里指定一个默认模型,新会话默认使用它。

本地模型 使用 Ollama 时先在本机启动 Ollama 服务并拉取好模型,再在「模型」里把 Codata 指向其本地端点。数据不出本机,适合对隐私敏感的场景。

MCP 接入

MCP(Model Context Protocol)让 Agent 连接外部数据源和工具。MCP 服务在 设置 →「插件」标签里管理。添加一个 MCP 服务通常只需要它的名称、URL,以及(如果需要)一个访问 Token。

打开设置 → 插件

进入设置,选择「插件」标签,这里集中管理 MCP 服务与扩展能力。

填写服务信息

填入 MCP 服务的名称与 URL;若该服务需要鉴权,再在 Token 输入框填入访问凭证。

打开开关启用

用开关启用该服务后,其提供的工具即可被 Agent 调用。不用时关闭开关即可停用,无需删除配置。

datasage 数据平台授权

Codata 内置了一个数据平台连接器:「datasage 数据平台」,服务地址为 https://datasage.flow.chat/mcp。接入后即可用自然语言查询、分析并出图。它在「插件」里作为内置服务出现,你只需要打开开关并完成授权。

打开 datasage 开关

在设置 →「插件」中找到「datasage 数据平台」,打开它的开关。

领取 MCP Key

前往 https://datasage.flow.chat/mcp-access 获取你的 MCP Key。

填入 Token 完成连接

把领取到的 MCP Key 填入下方的 Token 输入框,即可完成连接。

走 mcp-access 领取 Key datasage 的授权是打开开关后到 https://datasage.flow.chat/mcp-access 领取 MCP Key,再填入 Token 输入框——这是当前的流程,不是旧的知识库 token 流程。请以 mcp-access 领取到的 Key 为准。

权限与工作模式

Agent 在执行工具、运行命令或修改文件之前会请求授权。授权通过权限弹窗完成,已记住的授权可在 设置 →「权限」标签里查看和撤销。

读懂权限弹窗

当 Agent 需要执行工具或修改文件时会弹出请求,说明它要做什么。你可以选择「允许」或「拒绝」这一次操作,确认后 Agent 才会继续。

「记住此选择」

勾选「记住此选择」后,同类请求以后不再逐次询问,该选择会被记录下来。适合你已经信任的、会重复出现的操作。

在「权限」标签管理

设置 →「权限」列出所有已记住的授权,可逐条撤销,也可以全部清除。撤销后,相应操作会重新触发权限弹窗。

需要授权的操作 权限弹窗主要拦截工具执行、运行命令与文件修改这类有副作用的动作;纯粹的查询与分析一般不会打断你。给刚上手的团队成员先保持逐次确认,熟悉后再按需记住常用授权。

快速上手

下面用「十分钟第一个任务」跑通一次完整的问数闭环:提一个数据问题,看 Agent 如何发现表、生成 SQL、执行,并把结果整理成卡片和图表。

开始之前:先配置模型 第一次使用需要先连接一个可用模型(自有 API Key、OpenAI 兼容端点或本地 Ollama)。想做真实数据分析,还需要接入数据源(datasage MCP)。详细步骤见 配置详解,配置好至少一个模型后再回到这里。
打开应用

启动 Codata,进入问答首页。确认输入框上方的模型下拉里至少能看到一个可用模型;没有模型时先去 配置详解 配置。

输入一个数据问题

在首页输入框用业务语言提问,例如「上个月各渠道的日活趋势」。不用自己写 SQL、也不用先知道表名。

观察 Agent 工作

Agent 会先发现相关表和字段、优先匹配注册指标口径,再生成或复用 SQL 并执行查询;遇到错误会根据数据平台返回的信息自动修复。

查看结果卡片与图表

结果以结构化卡片展示,保留表格、SQL、字段和行数据。你可以核对 SQL 与口径,确认答案从哪里来,并让它渲染成图表。

钉到看板或导出

把有价值的图表钉到命名看板方便后续刷新,或让 Agent 把结果整理成报告导出。复杂问题还可以交给专家团做深度分析。

拿到结果后怎么继续 可以在同一会话里追问:「换成按周聚合」「加上环比」「只看华东区」「把这张图钉到『渠道大盘』看板」。Codata 会基于上下文继续调整 SQL 与图表,不用重头再来。

界面导览

Codata 的主界面可以分成几块:左侧会话栏、中间的问答首页 / 对话页、右侧工作栏与产物面板,以及设置中心入口。熟悉这几块的位置,日常使用就能顺畅切换。

左侧会话栏

查看历史会话、新建对话、搜索对话,并从这里进入设置。进入设置后会替换成专门的设置导航。

问答首页

包含欢迎语、输入框、模型下拉、工作模式、工作区按钮和附件按钮。所有任务都从这里发起。

对话页

显示用户消息、AI 流式回复、活动摘要、SQL 结果卡片、权限确认和追问输入框。

右侧工作栏

显示任务进度、生成文件、工作区记忆、连接器和技能等,配合对话查看当前任务的状态。

产物面板

把结果卡片、图表、Markdown / HTML 报告、表格和文件预览独立出来,方便在右侧查看与切换版本。

设置中心

从会话栏进入,集中管理外观、模型来源、权限、插件 / MCP、渠道、记忆、用量和更新。

设置中心标签一览

设置中心按下面几个标签组织。这里只列出各标签负责什么,详细配置步骤见 配置详解。

提示词写法

提示词不用复杂,但要说清楚。最稳定的结构是:目标 + 材料 + 输出格式 + 限制条件 + 受众。说清这几点,Agent 才能准确发现表、选对口径、生成合适的 SQL 和结果。

不推荐

「帮我看看销售数据。」

没有明确结果和范围,Agent 可能只给泛泛总结,或者用错口径。

推荐

「统计上个月各渠道的 GMV 和环比,找出增长最快和下滑最明显的渠道,输出汇总表格,并附上你用的 SQL 和口径说明。」

目标、材料、格式、限制和用途都清楚。

好提示词的组成部分

目标

说明最终要什么,例如「算 DAU 趋势」「找异常」「做一份留存分析」。

材料

说明看哪些数据、哪个时间范围、哪个业务口径,或指定用注册指标。

格式

说明输出成表格、图表、看板、报告,还是要附上 SQL。

限制

说明时间范围、维度、过滤条件,以及是否要说明口径来源。

受众

说明给老板、业务同事还是自己看,决定结论的详略和表达。

下一步

说明是否要钉到看板、导出报告,或继续追问下钻。

文件与工作区

除了连接数据源问数,Codata 也能处理本地文件。你可以上传单个文件做临时分析,也可以选择一个文件夹作为工作区,让 Agent 在其中读写、搜索并形成长期记忆。

什么时候用上传文件

  • 只需要处理一两份材料,例如一个 CSV 或 Excel。
  • 文件不在同一个文件夹里。
  • 只是临时分析,不需要形成长期记忆。

什么时候用工作区

  • 任务涉及一个文件夹里的多份文件。
  • 需要跨文件搜索和 @ 文件引用。
  • 需要生成文件并保存到这个项目目录。
  • 是长期项目,希望后续保留记忆。
安全建议 第一次不要把「整个电脑」交给 Agent。先建一个测试文件夹,把要处理的文件放进去,再选择这个文件夹作为工作区。

工作区记忆

每个工作区维护独立的记忆——它从对话中自动生成,为后续会话提供上下文,例如项目背景、常用口径和已完成事项。在工作区中开始对话后,记忆会自动生成;你可以在右侧工作栏查看,也可以在设置 →「记忆」标签中管理、删除,删除后后续对话会重新生成。

自动化任务

自动化适合重复的分析流程,例如每日数据摘要、每周指标周报、定期巡检和循环处理。任务同样在本机运行,按你设定的规则触发。

定时执行

按时间或间隔运行,例如每天 8:00、工作日 9:00 或每 2 小时一次。时间用 cron 格式配置:分 时 日 月 星期。

循环执行

让 Agent 反复执行提示词,每轮使用新的上下文,最多执行设定的迭代次数。在输出中包含 [LOOP_DONE] 可提前停止。

创建自动化的推荐流程

新建任务

进入自动化入口新建任务,填写名称和描述,例如「每日渠道数据摘要」。

写提示词

说明要查什么数据、输出什么、是否需要保存结果或钉到看板。

选择任务类型和时间

固定周期的任务选定时并配置 cron;需要持续处理队列的选循环并设定最大迭代次数。

选择模型和工作区

不确定模型可选自动;若涉及本地文件,工作区必须选准确。

先立即运行测试

手动跑一次确认结果正确,再开启定时开关。
