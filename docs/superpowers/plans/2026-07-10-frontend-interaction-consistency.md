# Codata 前端一致性整改计划

- 分支：`refactor/frontend-interaction-consistency`
- 范围：现有桌面端与 Web 前端的视觉、布局、交互和可访问性
- 原则：保持已有业务模块与数据流，不新增业务能力；只统一表达方式、修正交互路径和响应式行为

## 1. 现状结论

### 1.1 已有基础

- 全局已经有浅色/深色主题变量、数据侧边栏变量和 UI 字号变量。
- 设置、渠道、看板、专家团和聊天已经具备独立的真实功能入口。
- `PageFrame`、`PageHeader`、`SurfacePanel`、`StatusPill` 已提供页面级统一的基础组件。
- 关键用户路径已经有 Playwright UI 测试，当前 lint 与生产构建通过。

### 1.2 主要问题

1. **页面壳层不统一**：看板、自动化、知识、插件、MCP、技能等页面仍各自维护标题栏、内边距和滚动容器，导致标题字号、顶部间距和操作按钮位置不一致。
2. **层级密度不稳定**：专家团管理页、设置页部分二级标题仍偏大；卡片和说明文字在窗口较小时容易把主要操作推到首屏以下。
3. **颜色语义未完全收拢**：渠道页仍有平台色硬编码，这是品牌识别所需的例外；除此之外部分组件仍直接使用旧式透明色和 `text-white`，深色主题下容易出现对比不一致。
4. **侧边栏信息权重不稳定**：工作区入口、看板记录、最近会话和专家团标识需要保持同一行高、同一截断规则和明确的选中态，避免模式切换后产生重复入口或重叠。
5. **内容页缺少稳定的响应式契约**：左右面板、专家团进度、渠道配置和看板网格需要明确最小宽度、折叠/堆叠断点与溢出策略。
6. **交互反馈不够统一**：加载、空状态、错误、成功提示、危险操作和图标按钮的尺寸/文案/可访问标签需要统一。

## 2. 目标规范

### 2.1 页面框架

- 所有一级功能页统一使用 `PageFrame + PageContent + PageHeader`。
- 桌面端页面内容最大宽度默认为 `1440px`，管理型页面使用 `max-w-5xl` 或 `max-w-6xl`，不再在页面内重复定义另一套宽度。
- 一级标题使用 `text-ui-xl`，页面内二级标题使用 `text-ui-title-sm`；只有聊天欢迎页保留展示级字号。
- 页面背景使用 `surface-chat`，可交互内容使用 `surface-raised`，辅助区域使用 `surface-muted`，避免同一页面出现多种近似白色。

### 2.2 颜色与状态

- 品牌色只用于主操作、选中态、链接和数据高亮；不把整块页面染成品牌色。
- 成功、警告、危险状态统一使用 `StatusPill` 或全局语义变量的柔和背景。
- 平台 logo 的原生颜色保留在图标组件内部；平台列表之外不直接新增平台色。
- 所有可交互控件必须有 hover、focus-visible、disabled 三种状态。

### 2.3 交互与响应式

- `1024px` 以上保持桌面左右结构；低于该宽度，双栏页面按“主内容在前、详情在后”堆叠。
- 固定侧栏、右侧活动面板和内容区不得通过负 margin 或隐藏溢出互相覆盖。
- 图标按钮提供 `title` 或 `aria-label`；文字按钮保留明确动词。
- 空状态必须告诉用户当前模块没有数据以及现有功能允许的下一步，但不虚构不存在的能力。
- 切换 Chat/Codata 时先进入对应的新会话路由，历史会话按实际模式过滤。

### 当前验证备注

- 页面壳层与消息流视觉检查：6/6 通过（使用本机 Chrome，关闭 Playwright 视频录制）。
- 流式消息接管回归：6/6 通过，覆盖用户气泡单份、助手持久化回复单份和页面壳层布局。
- `lint`、`next build`：通过。
- 全量 UI preflight 被两条旧的 Chat 流程用例卡住；失败点是它们直接访问 `/c/new` 并期待 Chat 输入框，而产品当前约定是 Codata 默认。后续应让这些测试显式点击 Chat 模式，再继续完整回归。

## 4. 本轮优先落地

本轮先完成阶段 A 的剩余页面壳层迁移，以及阶段 B/C 中不会改变业务行为的统一样式和响应式约束。专家团内容区、看板内容卡和渠道详情属于高风险视觉区域，待基础壳层稳定后再逐页调整，并以现有 Playwright fixture 验证真实模块没有被删改。

## 5. 验收标准

- 页面之间的一级标题、描述、操作区和滚动边界一致。
- 现有功能入口、字段、按钮和 API 调用保持不变。
- 1440px 桌面视口无水平溢出；1024px 以下双栏内容不重叠；移动端可继续访问所有当前入口。
- 浅色和深色主题下，正文、边界、状态和主要操作均有稳定对比度。
- 现有 lint、build 和 UI preflight 全部通过。
