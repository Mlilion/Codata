# WorkCraft Release, Download, and Update Flow

This project uses GitHub Releases as the build source and `work-craft.com` as
the stable public download/update endpoint.

## Public files

The release workflow publishes these files to `/opt/workcraft` on the website
server:

- `/opt/workcraft/downloads/latest.json`
- `/opt/workcraft/update/latest.json`
- `/opt/workcraft/downloads/releases/<tag>/*`

Website users download installers from `/downloads/latest.json`.
The Tauri desktop updater checks `/update/latest.json`.

## Required GitHub Actions secrets

Set these under repository or organization **Actions secrets**:

- `TAURI_SIGNING_PRIVATE_KEY`: updater private key file content generated by
  `npx @tauri-apps/cli signer generate`. The generated file content is already
  base64 text; paste it as-is.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password for the private key. Leave
  unset only if the generated key has no password.
- `APPLE_CERTIFICATE`: base64 encoded Developer ID Application `.p12`
  certificate for macOS code signing.
- `APPLE_CERTIFICATE_PASSWORD`: password for the `.p12` certificate.
- `APPLE_SIGNING_IDENTITY`: Developer ID Application signing identity name.
- macOS notarization credentials. Use either `APPLE_ID`,
  `APPLE_PASSWORD`, and `APPLE_TEAM_ID`, or use `APPLE_API_ISSUER`,
  `APPLE_API_KEY`, and `APPLE_API_KEY_PATH`/`APPLE_API_KEY_PRIVATE_KEY`.
- `WORKCRAFT_WEB_HOST`: website server host.
- `WORKCRAFT_WEB_USER`: SSH user that can write `/opt/workcraft`.
- `WORKCRAFT_WEB_SSH_KEY`: private SSH key for that user.
- `WORKCRAFT_WEB_PORT`: optional SSH port. Defaults to `22`.

If you store them as GitHub Environment secrets instead, the release workflow
jobs must declare the same `environment:` name or GitHub will not inject them.

The updater public key is already configured in
`desktop-tauri/src-tauri/tauri.conf.json`.

Do not put the public key from `tauri.conf.json` in the private key secret.
Existing desktop clients will only accept updates signed by the private key
that matches the public key already shipped in `tauri.conf.json`. Regenerating a
new key pair requires shipping a new installer first; it cannot update older
clients that trust the previous public key.

## Release process

1. Bump the root `package.json` version.
2. Run `npm run sync:desktop-meta` so Tauri metadata matches the app version.
3. Commit the version changes.
4. Push a tag such as `v1.1.1`.
5. The `Release Desktop` workflow builds platform artifacts, signs updater
   artifacts, creates a draft GitHub Release, and syncs the website files.
6. Publish the draft GitHub Release after checking the assets.

## Server check

After a release, verify:

```bash
curl -fsSL https://work-craft.com/downloads/latest.json
curl -fsSL https://work-craft.com/update/latest.json
```

The NGINX/Cloudflare config should keep both `latest.json` files uncached and
must not cache 404 responses for `/downloads/releases/*`. The release workflow
uploads versioned assets before publishing the two manifests so clients do not
see a new manifest until its files are already present.
