产品概述

什么是 WorkCraft Agents

WorkCraft Agents 是 WorkCraft 桌面端中的智能体工作流。它不是单纯的聊天窗口，而是把自然语言任务、文件读取、工作区搜索、工具执行、产物生成、权限确认和多专家协作放到同一个可追踪流程中。用户可以用一句话描述目标，也可以附加文件、选择工作区、指定模型和权限边界，让 WorkCraft 按步骤推进任务。

在 WorkCraft 中，普通任务通常从问答首页开始；复杂任务可以选择专家团，让多个专业角色分工处理；重复任务可以进一步固化为自动化或模板。

核心优势

本地优先工作台

桌面端负责会话、文件、工作区和生成产物的本地组织。使用云模型时只发送完成任务所需上下文；使用 Ollama 等本地模型时可减少云端调用。

真实文件处理

支持 DOCX、XLSX、PPTX、PDF、CSV、图片、Markdown、文本和代码文件。可以上传附件，也可以选择项目文件夹作为工作区。

可见的执行过程

对话中会展示推理、工具调用、读取/写入文件、命令执行、上下文压缩、计划审查和错误恢复，便于检查过程而不是只看最后答案。

可验收产物

结果可以进入右侧产物面板，形成 Markdown 报告、HTML 页面、表格、代码、文件预览或最终导出文件。

专家团协作

可把复杂任务拆给数据、研究、写作、审校、风险、工程等专家角色执行，再由协调者或 Manager 汇总最终结果。

多模型与扩展

支持官方模型、自有 API Key、ChatGPT 订阅、本地模型和 OpenAI 兼容端点，也能接入 MCP 连接器、插件、技能和消息渠道。

适用场景

下载与安装

WorkCraft 通过公开下载页提供桌面端安装包。访问 work-craft.com/download 下载适合当前系统的版本；发布后的安装包也会写入公开下载清单 https://work-craft.com/downloads/latest.json。

平台 架构 安装包格式 安装方式
macOS Apple Silicon / Intel .dmg、.app 下载后打开 .dmg，按系统提示安装并启动 WorkCraft。
Windows x64 .exe 安装包 下载安装包后运行，按安装向导完成安装。
Linux x64 .deb、.rpm 按发行版选择包格式；依赖和排障说明可参考仓库中的 LINUX.md。
1
打开下载页

进入 work-craft.com/download，选择与系统和架构匹配的安装包。

2
安装桌面端

按系统提示完成安装。首次启动后，WorkCraft 会同时启动本机后端服务，用于文件处理、会话存储和工具执行。

3
完成首次配置

进入设置页配置模型来源。可使用 WorkCraft 账户、自有 API Key、ChatGPT 订阅、本地 Ollama 或 OpenAI 兼容端点。

4
检查更新

桌面端设置中的“关于 / 软件更新”可检查新版本。WorkCraft 的桌面更新会读取公开更新清单 https://work-craft.com/update/latest.json。

下载失败时

先确认网络和系统架构，再重新打开下载页。若安装包能下载但应用无法启动，优先检查系统安全提示、Linux 依赖或是否被旧版本进程占用。

环境要求

WorkCraft 是桌面端 AI 工作台，基础链路需要应用本体、一个可用模型来源和一个明确的任务材料范围。第一次使用不建议直接开放整个电脑，先用一个测试文件夹验证流程。

系统

安装对应系统的 WorkCraft 桌面端。应用启动后会在本机运行后端服务，用于会话、文件处理、流式任务和工具调用。

模型来源

至少配置一个可用模型来源：WorkCraft 账户、自有 API Key、ChatGPT 订阅、Ollama、本地 API 或 OpenAI 兼容端点。

工作区

处理项目资料时选择一个边界清晰的文件夹。仅分析单个材料时可以直接上传附件。

网络

使用云模型、网页搜索、远程 MCP、远程专家团 manifest 或消息渠道时需要网络。纯本地模型与本地文件任务可减少网络依赖。

可选扩展

如需本地模型，先安装并启动 Ollama；如需外部工具，配置 MCP 连接器；如需 IM 助手，配置飞书、钉钉、微信、企业微信、QQ 或 Telegram。

权限准备

文件修改、命令执行和外部工具调用可能触发权限确认。新手建议从“先规划”或“先询问”开始。

首次使用建议

准备一份无敏感信息的测试文档和一个小型测试文件夹。确认模型回复、文件读取、产物预览和权限确认都正常后，再处理正式资料。

在 WorkCraft 中进入智能体模式

WorkCraft 没有把入口命名为 IDE 的“Agent Mode”，但问答首页就是 WorkCraft Agents 的主要执行入口。你可以在同一个输入区完成模型选择、工作区选择、文件附加、权限模式设置和专家团选择。

1
打开问答首页或新建会话

从左侧栏进入新建对话。历史会话可继续追问、补充文件或修改已经生成的产物。

2
选择模型和执行策略

日常任务可使用默认模型；复杂长文档、强推理或工具调用任务应选择稳定且上下文足够的模型。

3
指定材料范围

上传附件处理单次材料；选择工作区处理项目文件夹；在输入框中使用 @ 精确引用工作区文件。

4
设置权限边界

高风险任务先使用“先规划”或“先询问”。需要写文件、移动文件或运行命令时，先检查路径和影响范围。

5
需要多角色时选择专家团

在专家团页面点击“召唤”，或在会话输入区选择专家团，让任务按预设的专家成员和流程执行。

发起您的第一个任务

一个稳定的 WorkCraft 任务通常包含四类信息：目标、材料、输出、限制。不要只输入“帮我看看”，而要说明结果要给谁看、需要什么格式、哪些信息不能编造、是否允许修改文件。

第一个任务示例
请阅读我上传的文件，整理成一份适合发给团队负责人的 brief。
请输出：
1. 三条关键结论
2. 风险与待确认事项
3. 行动项表格：事项、负责人、截止日期、优先级
4. 一封可以直接发送的跟进邮件
要求：不要编造文件中没有的信息，不确定的地方标注“待确认”。
1
附加文件

拖拽文件或通过文件选择器上传。处理项目时先选择工作区，再用 @ 引用关键文件。

2
发送任务

观察模型是否开始流式回复。若需要读取文件、搜索目录、写入结果或运行命令，对话中会显示相应步骤。

3
检查过程

展开工具调用、活动面板和权限请求，确认它读取了正确文件、没有越界操作。

4
验收结果

查看右侧产物面板或最终回复，要求补充缺失信息、改写口径、导出文件或保存到工作区。

完成判断

如果模型能回复、文件卡片能被读取、右侧能显示活动或产物，说明基础链路已可用。下一步可以尝试工作区、多文件任务或专家团。

对话与会话

会话是 WorkCraft 组织任务上下文的基本单位。一个会话可以继续追问、追加文件、修改产物或导出归档。长会话达到阈值后，WorkCraft 会压缩旧上下文，减少重新开始任务的成本。

结果查看与产物

Artifact 是 WorkCraft 中可复用、可预览、可导出的结果块。它可以是 Markdown、HTML、代码、表格、图表、PDF/DOCX/PPTX/XLSX 文件预览，也可以是专家团最终交付生成的文件。

模式与权限

模式 含义 适合场景
先规划先分析、列计划和影响范围，不直接修改文件。重要文件、批量整理、第一次执行复杂任务。
先询问涉及写文件、编辑或命令执行时请求确认。日常办公和风险可控任务。
自动修改在权限规则允许范围内自动执行修改。低风险、已验证、重复性强的任务。
权限弹窗检查项

确认文件路径、操作类型、命令内容和影响范围。不确定时拒绝操作，并要求 WorkCraft 解释目的和替代方案。

自动化

自动化适合把稳定、重复、低风险的任务交给 WorkCraft 定期或循环执行。建议先手动运行一次，检查输出和权限，再启用定时。

定时执行

按 cron 或固定间隔运行，例如每天 8:00、工作日 9:00、每两小时一次。

循环执行

按最大轮数持续执行，输出中包含约定结束标记时可提前停止。

模板任务

从内置模板创建每日摘要、周报、文件同步、定期检查等任务。

专家团模块深度指南

专家团是 WorkCraft 处理复杂任务的核心模块。它把一个大任务拆成多个专家成员和多个任务节点，让每个角色只负责自己擅长的部分，再通过协调者、最终交付配置或 Hierarchical Manager 汇总为用户可验收的结果。

核心理解

普通对话适合“一个 AI 直接完成”；专家团适合“多角色分工、阶段明确、需要审阅或最终产物合同”的任务。

专家团是什么

一个专家团由 ExpertTeamConfig 定义，包含团队基本信息、专家成员、任务流程、运行模式、输入项、上下文规则、最终交付规则和运行元数据。运行时，WorkCraft 会按配置创建专家任务，把用户输入、附件、工作区和上游输出传给对应专家。

用户输入目标、附件、工作区、补充说明、模型和权限规则。
预检提问协调员可在开始前检查信息缺口，并按配置向用户提问。
专家执行按顺序、DAG 工作流或 Manager 委派执行任务。
上下文传递下游任务可以引用上游输出变量，也可以接收摘要或完整依赖结果。
最终交付由最后任务、协调者或交付专员生成 Markdown、HTML、PDF、DOCX、XLSX、PPTX、代码、图片、视频或 Artifact。

什么时候应该使用专家团

  • 任务天然需要多个视角，例如市场、法务、财务、产品、风险共同审阅一份方案。
  • 任务阶段明确，例如资料研究、数据准备、洞察分析、报告撰写、最终审校。
  • 需要可复用流程，例如每周固定生成经营分析报告或客户提案。
  • 需要最终产物合同，例如必须生成 HTML 页面、PPT 大纲、Excel 表格或可预览文件。
  • 需要动态调度，例如任务边界不清、需要 Manager 多轮委派不同专家。

三种执行模式

模式 运行方式 适合任务 配置要点
sequential 顺序 按任务列表顺序执行。若任务没有显式依赖，系统会自动把后一个任务依赖到前一个任务。 固定流水线：研究 → 初稿 → 审校 → 汇总。 并发固定为 1；适合简单、线性的专家协作。
workflow 工作流 按 depends_on 构建 DAG，满足依赖后执行，支持 1-8 并发。 有并行分支的流程：市场和竞品可并行调研，再汇总策略。 必须认真配置依赖、输出变量和并发，避免循环依赖。
hierarchical 层级调度 Manager 负责规划、委派、追问同事专家并综合最终答案。 需求边界不清、需要动态委派、多轮协调、跨角色反复确认的任务。 需要配置 Manager、子模式和最大委派次数；autonomous 子模式可以没有预设任务。

Hierarchical Manager 详解

Hierarchical 模式会运行一个 Manager 角色。Manager 可以把具体任务委派给 coworker 专家，也可以向某个专家追问。底层使用两个合成工具：delegate_work 和 ask_coworker。这让专家团不必把所有步骤写死，适合复杂、开放、需要临场判断的任务。

coordinated

配置中的 tasks 作为建议计划。Manager 可以参考这些任务并动态调整，适合“有大致流程但需要灵活协调”的任务。

autonomous

可以不配置任务，由 Manager 根据用户输入动态派活。适合探索型任务，但应限制最大委派次数和最终交付要求。

id / name团队唯一标识和显示名称。ID 使用英文、数字、下划线或短横线；名称面向用户可读。
description / tags / category说明适合处理什么任务，便于搜索和分类。描述写清输入材料、处理流程和最终产物。
process / concurrency执行模式和并发数。固定线性用顺序；固定 DAG 用工作流；动态委派用 Hierarchical。
inputs运行前要收集的结构化输入项。用于报告周期、目标受众、输出语言、业务线等固定参数。
members专家成员列表。通常 2-5 位，角色边界要清晰。
tasks任务节点列表。通常 2-7 个任务，每个任务有负责人、依赖、期望输出和输出变量。
finalization最终答复或产物生成规则。默认建议使用 deliverable，让最终结果进入产物面板或文件预览。
manager / max_delegationsHierarchical 模式的 Manager 配置。限制最大委派次数，避免开放任务无限扩张。
interaction_mode专家团开始前是否向用户补充提问。资料不足时用 auto 或 ask_first；稳定自动化可用 off。
coordinator_prompt最终协调者如何整合专家输出。写清冲突处理、事实保留、行动建议和格式要求。

专家成员配置

专家成员决定“谁来做”。每位成员可以配置角色、目标、背景、角色库引用、系统提示词、模型、工具、技能和连接器。

配置项 说明 实践建议
role / goal角色定位和工作目标。目标写成可执行职责，不要只写“专家”。
role_ref / role_source引用 agency-agents-zh 或兜底角色库。优先使用中文角色库，生成团队时也会倾向选择已有角色。
system_prompt角色系统提示词快照。适合固定口径、审查标准、行业规则或输出风格。
model / provider_id为某个专家指定模型。让研究、分析、写作使用不同成本和能力的模型。
tools允许专家使用的工具。常见工具包括 read、glob、grep、search、web_search、web_fetch、skill、code_execute、write、edit、bash。
skills / connectors预加载技能或 MCP 连接器。只给需要的专家开放，减少误用和上下文噪声。
工具授权建议

默认给研究和分析专家 read、grep、skill、code_execute 已经足够。只有明确需要落地文件或执行命令时，才给 write、edit、bash。

任务流程配置

任务节点决定“怎么做”。每个任务包含 ID、名称、描述、负责人、依赖、输出变量、上下文策略、条件、超时、重试和最大工具轮数。

配置项 作用 示例
member指定执行该任务的专家成员。analyst、reporter
depends_on / context声明上游任务依赖。两个字段兼容，保存时会同步。["research"]
depends_on_mode多个依赖是全部完成还是任一完成即可。all 或 any_completed
output把该任务结果命名为变量，供下游模板引用。research_report
context_policy控制依赖输出如何进入下游提示词。auto、explicit、dependencies、summary
condition根据上下文判断是否执行。{{review}} contains 通过
timeout_seconds / retry_count单个任务超时和失败重试。默认 300 秒，重试 1 次。
loop配置回到上游任务的循环。用于“生成 → 审查 → 修订”的有限迭代。

上下文与变量引用

任务说明可以使用模板变量。WorkCraft 会在运行前校验变量是否可用，避免下游任务引用不存在或非上游的输出。

变量 含义
{{user_input}} / {{input}}用户本次召唤专家团时输入的任务。
{{workspace}}当前工作区信息。
{{attachments}}用户附加文件信息。
{{clarifications}}预检阶段用户补充的回答。
{{research_report}}上游任务通过 output: research_report 产出的结果。
{{input_name}}团队 inputs 中定义的结构化输入。
上下文策略怎么选

explicit 只使用你在模板中写出的变量；dependencies 会加入依赖完整输出；summary 会偏向摘要；auto 让系统根据任务自动处理。长文档或多专家输出较大时，优先使用 summary 并设置 context_max_chars。

最终交付配置

finalization 决定专家团完成后如何把结果交付给用户。WorkCraft 支持四种收尾模式。

模式 说明 适合场景
deliverable生成明确产物，可进入产物面板或文件预览。报告、网页、表格、PPT、代码、视频等可验收结果。
coordinator由协调者综合所有专家输出生成最终答复。咨询、审阅、决策建议。
last_task直接使用最后一个任务输出。简单线性流程。
none不额外收尾。仅调试流程或只关心中间任务输出。

当 mode 为 deliverable 时，需要声明产物类型、标题、文件名模板、来源、展示方式和工具。产物类型包括 markdown、html、pdf、docx、xlsx、pptx、image、video、code、artifact。展示方式包括 artifact_panel、file_preview、both。

AI 创建专家团

专家团页的“AI 创建”会创建一个特殊会话，让 WorkCraft 作为专家团架构师输出可执行的 ExpertTeamConfig JSON。生成逻辑会优先选择合适流程：简单固定顺序用 sequential，固定 DAG 或可并发流程用 workflow，需要 Manager 统筹、动态委派或需求边界不确定时用 hierarchical。

AI 创建专家团提示词
请帮我创建一个 WorkCraft 专家团。
业务目标：每周读取销售数据和客户反馈，输出经营分析报告。
输入材料：Excel 销售表、客户反馈文本、上周行动项。
需要角色：数据准备、洞察分析、业务策略、报告撰写、审校。
执行方式：数据准备后，洞察分析和客户反馈分析可并行，最后汇总为 Markdown 报告和行动项表格。
交付要求：最终生成可在产物面板查看的 Markdown 报告，包含风险、机会、下周建议和待确认问题。
权限限制：默认只读，除最终交付外不要写文件。

召唤专家团并运行

1
打开专家团详情

在专家团页按分类或搜索找到团队，查看成员、流程、任务和来源。

2
点击召唤

WorkCraft 会创建一个新会话，并把该专家团绑定到会话输入区。

3
输入本次任务

说明目标、材料、输出、限制，必要时附加文件或选择工作区。

4
回答预检问题

如果配置允许，协调员会在执行前询问信息缺口。超时后可继续基于假设执行或失败，取决于配置。

5
查看进度和交付

右侧专家团视图显示成员分工、任务状态和输出。最终产物会进入对话或产物面板。

恢复专家团任务

专家团支持从指定任务恢复执行。普通工作流可以从某个任务 ID 继续；Hierarchical 模式还可以从 __manager__ 恢复。恢复时，WorkCraft 会读取该会话里上一次专家团请求和已产生输出，减少长流程失败后从头再来的成本。

预设、自定义、项目级、远程专家团

来源 说明 能否编辑
presetWorkCraft 内置专家团，例如数据分析、内容创作、软件开发、视频生成等。通常只读，可复制为自定义。
user用户在专家团页创建或复制出来的团队。可编辑、删除。
project项目级专家团，通常来自工作区内的 .workcraft/expert-teams。取决于来源配置。
remote通过 manifest 加载的远程专家团。只读；远程 ID 与本地冲突时本地优先。

远程专家团默认关闭。启用后可通过本地 JSON 文件或 HTTP manifest 加载，缓存路径通常位于 ~/.workcraft/remote-expert-teams/cache/manifest.json。只有授权有效、未过期、且可见的远程团队会被加载；单个无效条目会被跳过，不影响其他远程团队。

校验规则与常见错误

  • 成员 ID 和任务 ID 不能重复。
  • 任务引用的 member 必须存在。
  • 任务依赖必须存在，不能依赖自己，DAG 不能出现循环。
  • 输出变量通常应由唯一任务产生，除非用于特定 any_completed 或循环场景。
  • 任务模板只能引用 {{user_input}}、{{input}}、{{workspace}}、{{attachments}}、{{clarifications}}、团队输入项和上游输出。
  • 最终交付来源必须是 last_task、coordinator、某个任务 ID 或某个输出变量。
  • 非 autonomous Hierarchical 专家团至少需要一个任务；autonomous Hierarchical 可以没有任务，由 Manager 动态派活。

专家团最佳实践

推荐做法
  • 先写清团队适用场景和最终产物。
  • 角色通常控制在 2-5 位，任务控制在 2-7 个。
  • 每个任务都配置清晰的 expected_output。
  • 下游任务使用输出变量，而不是让模型猜上游内容。
  • 最终交付优先使用 deliverable。
  • 高风险工具只给确实需要的成员。
避免做法
  • 把所有专家都写成“通用助手”。
  • 没有依赖关系却使用复杂工作流。
  • 给每个成员都开放 write、edit、bash。
  • 让多个任务产出同名变量。
  • 没有最终交付配置，只在最后回复一段泛泛总结。
  • 远程专家团和本地自定义团队使用相同 ID。

插件、连接器与技能

插件、连接器和技能都用于扩展 WorkCraft，但分工不同。连接器把外部 MCP 服务接入 WorkCraft；插件提供可启停的扩展能力；技能是面向特定任务的操作指南，会帮助 AI 按专业流程工作。

类型 用途 常见操作
连接器把外部 MCP 服务接入 WorkCraft，让 Agent 获得额外工具。连接、授权、断开、重连、添加自定义 MCP 地址。
插件提供一组可启用或停用的扩展能力，可能包含工具和技能。查看版本、描述、依赖，启用或停用插件。
技能针对特定任务的工作指南。查看技能正文、启用内置/插件/项目技能，从技能商店安装。
使用建议

先熟悉基础文件任务，再逐步启用连接器和技能。对不了解的外部服务，先在测试工作区验证。

配置与安全

模型配置

WorkCraft 支持多模型来源并行配置。你可以随时切换默认模型，也可以给专家团成员单独指定模型。

来源 适合用户 说明
WorkCraft 账户想快速使用官方模型和积分体系。登录后同步模型、积分和高级功能。
自有 API Key已有服务商账号和预算管理体系。可接入 OpenAI、Anthropic、Google Gemini、DeepSeek、Qwen、Kimi、Azure OpenAI 等兼容来源。
ChatGPT 订阅已有 ChatGPT Plus / Pro / Team / Enterprise。通过授权接入已有订阅能力。
Ollama 本地模型希望离线处理或减少云端调用。可下载、启动、停止、删除本地模型，效果取决于硬件和模型。
本地 API / 自定义端点公司内网、私有模型或高级用户。连接兼容 OpenAI /v1/chat/completions 的接口。

用量与账户

用量页用于查看 token、成本、响应时间、模型占比和高消耗会话。账户页用于登录、查看积分、充值、订阅和支付记录。大文件、长会话、昂贵模型和高频自动化会显著增加消耗。

数据与安全

建议做法
  • 重要文件先备份。
  • 复杂任务先用“先规划”。
  • 每个项目选择明确工作区。
  • 权限弹窗认真看路径和命令。
  • 敏感资料优先脱敏或使用本地模型。
  • 自动化先手动测试，再启用定时。
避免做法
  • 第一次就开放整个电脑给 AI 操作。
  • 不看路径就允许写入、编辑或执行命令。
  • 把密钥、证件号、银行卡等直接发送给云模型。
  • 对不了解的命令选择长期记住允许。
  • 长期启用自动化但不检查运行历史。

常见问题

问题 可能原因 处理方式
没有可用模型未登录账户、API Key 未配置、Ollama 未启动或服务商不可用。进入设置 → 模型或账户，配置至少一个可用来源并测试连接。
文件读取失败文件被占用、路径不可读、格式异常、工作区范围不包含该文件。关闭占用程序，重新附加文件，或把文件放入当前工作区。
AI 找不到文件没有选择工作区、文件未被索引、文件名不明确。重新选择工作区，使用 @ 精确引用文件。
结果太泛泛提示词只描述“看看”“分析一下”，没有交付标准。补充受众、输出格式、字段、字数、限制和验收标准。
专家团保存失败成员 ID 重复、任务依赖不存在、变量引用错误或最终交付来源错误。按校验提示修复 ID、依赖、输出变量和交付来源。
专家团运行太慢成员多、任务多、模型慢、上下文过长或工具轮数过高。减少成员和任务、降低上下文上限、缩小文件范围，或把 workflow 并发设置到合理值。
自动化没有运行任务未启用、调度时间错误、模型不可用或工作区路径变化。检查开关、下次运行时间、模型和工作区，先点“立即运行”。
成本上涨快文件过大、会话很长、模型价格高、自动化频率过高。在用量页查看高消耗会话，换低价或本地模型，减少自动化频率。
