# Codata 前端交互与视觉一致性整改计划

## 1. 整改目标

本次整改以现有功能为边界，不新增产品模块，不改变后端接口语义。目标是修复跨页面交互冲突，统一视觉语言，提升窄屏、暗色模式、键盘操作和错误状态下的可用性。

整改完成后应满足：

- Chat 与 Codata 模式切换、路由和会话类型保持一致。
- 桌面左右侧栏不会把主内容压缩到不可用宽度，移动端可以访问真实的 Codata 功能。
- 通用、模型、权限、插件、渠道、用量、记忆、关于使用同一设置页面骨架。
- 专家团消息区展示分析细节，右侧功能区只承担进度、状态和工具调用。
- 看板、自动化、技能、MCP、知识库与专家团遵循统一的页面标题、间距、按钮和危险操作规则。
- 浅色、暗色和主要窗口宽度均有自动化验证。

## 2. 实施原则

1. 保留现有功能和数据结构，优先调整状态流、布局和表现层。
2. 先修复功能性冲突，再抽取设计规范，最后逐页迁移。
3. 每个阶段独立提交，避免一个提交同时包含状态重构和大面积样式修改。
4. 共享组件只在至少两个真实页面需要时抽取，不为设计稿虚构功能。
5. 所有颜色、字号、圆角和语义状态优先使用全局变量，不在业务页面重复写死。

## 3. 当前基线

- 基线分支：`refactor/frontend-interaction-consistency`
- 基线来源：`fix/desktop-routing-and-hide-knowledge` 当前最新提交
- ESLint：通过
- TypeScript `--noEmit`：通过
- 已确认的主要风险：模式状态冲突、双侧栏挤压、渠道页固定宽度、暗色模式断裂、专家团信息重复、危险操作不统一、移动端导航缺失、视觉测试不足。

## 4. 分阶段整改

### 阶段一：模式与导航状态

改动范围：

- 将当前会话的 `app_mode` 作为会话页模式的事实来源。
- 打开普通 Chat 会话时显式切换到 Chat，打开 Codata 会话时切换到 Codata。
- 顶部 Chat/Codata 切换改为“设置模式并导航”，避免停留在不兼容路由。
- 统一搜索结果、最近会话和深链进入后的模式标识。
- 移动抽屉根据模式展示普通会话导航或 Codata 的看板、专家团和分析记录。

验收标准：

- 在 `/experts`、`/dashboard` 点击 Chat 能进入 Chat 工作区，不会被立即切回。
- 直接打开任意历史会话时，侧边栏和消息样式与会话类型一致。
- 桌面和移动端切换结果一致。

### 阶段二：应用外壳与响应式

改动范围：

- 建立主内容最小宽度规则，动态限制左右侧栏总宽度。
- 中等宽度下右侧功能区改为覆盖式面板，避免同时挤压主内容。
- 统一页面滚动归属，避免外层和内容区双重滚动。
- 修复独立渠道页容器与内部最小宽度冲突。
- 看板在窄屏切换为单列或响应式网格，专家团时间线改为移动端纵向结构。

验收标准：

- `1024px` 宽度下聊天正文、输入框和右侧面板均可正常使用。
- `390px` 宽度下无页面级横向滚动，表格和代码块使用局部滚动。
- 左右侧栏拖拽后重新打开窗口仍保持可用尺寸。

### 阶段三：设计系统收口

改动范围：

- 完善背景、面板、边框、品牌色、成功/警告/危险状态的浅色和暗色变量。
- 调整辅助文字颜色，普通小字号文本对比度达到可读标准。
- 固化页面标题、正文、说明、标签和数据字号层级。
- 固化控件、卡片、面板、弹窗的圆角层级。
- 新增共享的 `PageShell`、`PageHeader`、`SplitView`、`DetailPanel`、`StatusPill` 等页面级组件。

验收标准：

- 业务页面不再新增无语义的十六进制颜色。
- 页面标题位置、左右内边距、工具栏高度和内容最大宽度保持一致。
- 暗色模式不出现非预览用途的突兀白色业务卡片。

### 阶段四：设置页面统一

改动范围：

- 通用、模型、权限、插件、渠道、用量、记忆、关于统一使用设置页工作区骨架。
- 渠道页移除固定浅色值，左右分栏根据可用宽度响应式调整。
- KaonRouter 保留公司预设逻辑，只统一卡片和表单表现。
- 清理无效使用文档入口及残留文案。
- 设置搜索继续只搜索现有设置模块，不增加不存在的业务入口。

验收标准：

- 八个设置模块切换时标题、留白、滚动位置和内容宽度稳定。
- 渠道扫码、手动配置、断开连接和错误反馈功能不回归。
- KaonRouter 固定 URL 和仅填写个人 Key 的逻辑不变。

### 阶段五：聊天与专家团调用

改动范围：

- 精简 Chat 顶部无真实信息价值的 `workspace` 标签，展示真实工作区或不展示。
- 统一落地页与会话页输入框、消息间距和助手身份区域。
- 专家团消息区保留专家观点、详细过程、结论和交付物。
- 从消息区移除重复的工具调用清单和进度元数据。
- 右侧专家团面板集中展示步骤状态、进度、工具、失败与恢复入口。

验收标准：

- 长专家团任务不会在消息区和右侧面板重复出现同一批工具记录。
- 关闭右侧面板后，消息区仍然具备完整的业务阅读价值。
- 打开右侧面板后，可以快速判断当前步骤、完成比例和失败位置。

### 阶段六：业务页面统一

改动范围：

- 专家团管理、看板、自动化、技能、MCP、知识库迁移到统一页面骨架。
- 统一列表密度、搜索框、空状态、加载状态和错误状态。
- 看板、知识库、专家团、自动化统一危险操作确认组件。
- 自动化创建和编辑弹窗迁移到项目现有 Radix Dialog。
- 处理同一功能在独立页和设置页中的容器重复问题。

验收标准：

- 删除、保存、运行、刷新均有一致的进行中、成功和失败反馈。
- 所有弹窗支持 Escape、焦点锁定和关闭后的焦点恢复。
- 页面之间不再出现明显不同的标题字号和首屏留白。

### 阶段七：国际化、可访问性与反馈

改动范围：

- 将界面内残留的中英文硬编码迁移到现有语言资源。
- 为图标按钮补充可访问名称和 Tooltip。
- 关联表单标签与控件，错误消息使用 `aria-describedby` 或等价语义。
- 修复仅依赖 hover 出现的操作按钮，补充键盘焦点状态。
- PDF 导出、专家团恢复、文件选择等失败场景提供用户可见反馈。

验收标准：

- 中文和英文模式下不存在明显混合文案。
- 仅使用键盘可以完成主导航、发送消息、配置渠道和创建自动化。
- 关键小字号文字达到 WCAG AA 常规文本对比度目标。

### 阶段八：测试与视觉验收

自动化矩阵：

| 范围 | 视口 | 主题 |
| --- | --- | --- |
| 桌面标准 | 1440 x 960 | 浅色、暗色 |
| 笔记本 | 1280 x 800 | 浅色、暗色 |
| 最小桌面 | 1024 x 768 | 浅色、暗色 |
| 移动端 | 390 x 844 | 浅色、暗色 |

覆盖流程：

- Chat/Codata 切换与历史会话深链。
- 新建分析、普通对话和专家团调用。
- 看板创建、重命名、布局、刷新和删除。
- 设置八个模块切换，KaonRouter 配置和渠道连接。
- 自动化创建、运行、历史、编辑和删除。
- 左右侧栏展开、收起、拖拽和窗口缩放。

完成条件：

- ESLint、TypeScript、构建和 UI 测试通过。
- 主要页面无非预期横向滚动、遮挡或文本溢出。
- 浅色和暗色截图经过人工对比确认。

## 5. 提交策略

建议按以下边界拆分提交：

1. `fix(ui): synchronize app mode with routes and sessions`
2. `fix(ui): make app shell and side panels responsive`
3. `refactor(ui): consolidate design tokens and page primitives`
4. `refactor(settings): unify settings workspace and channel layout`
5. `refactor(experts): separate message detail from execution progress`
6. `refactor(ui): align dashboard automation and utility pages`
7. `fix(a11y): normalize dialogs labels focus and destructive actions`
8. `test(ui): add theme and responsive regression coverage`

每个提交完成后单独运行相关测试，最终再执行完整验证，便于定位回归和必要时安全回退。

## 6. 非目标

- 不新增当前代码中不存在的业务模块。
- 不修改专家团、渠道、看板、自动化的后端协议。
- 不改变 KaonRouter 固定地址和公司预设模型的产品规则。
- 不借整改机会进行无关的依赖升级或大规模目录重排。
