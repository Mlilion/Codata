# 报告可信度约束

数据报告的价值建立在「可信」之上。生成任何 HTML 报告都必须满足以下四条硬约束。违反其一，报告即不可交付。

---

## 一、口径声明

每个出现在报告里的核心指标，都必须在「口径与数据来源声明」段落声明其口径。分两类：

- **注册口径**：来自指标中心 / search_indicators 的已注册指标。格式：
  `指标名 = 指标中心口径（indicator_code: xxx），来源表 db.table`。可标「✅ 已验证口径」。
- **自定义口径**：分析中临时用 SQL 现算、指标中心没有登记的口径。必须显式加警示：
  `⚠️ 自定义口径，未经指标中心验证` —— 让读者知道这个数字未经权威校验，需自行判断。

不允许出现「口径不明」的指标。若无法确定口径，宁可不放该指标。

## 二、数据截至时间（as-of）

- 报告头必须标注「**数据截至** YYYY-MM-DD [HH:MM]」，说明数据快照的时间点。
- 「口径与数据来源声明」段落里，每个指标/数据源也要重申其数据截至时间（不同源可能不同步）。
- 数据截至时间反映数据的时效边界，是读者判断结论是否过期的依据，不可省略。

## 三、事实 / 推断 / 建议 三分

「归因与洞察」段落里的每条结论都要归类，并在视觉上区分（不同标签 + 不同颜色）：

- **事实**（标签蓝/中性色）：直接来自查询结果的客观数字与变化，可被数据复核。
  例：「7 月 GMV 环比下降 12%」。
- **推断**（标签橙/警示色）：基于数据的因果或归因判断，非直接观测，可能有其他解释。
  例：「下降主要由华东区退款激增导致（推断）」。
- **建议**（标签绿/行动色）：给业务方的行动项，属主观建议，需业务判断。
  例：「建议排查华东区退款流程（建议）」。

三类标签样式在 `report-shell.html` 里预置，直接套用，不要把推断写成事实。

## 四、不编造原则

- 只使用真实查询结果里的数字，禁止估算、凑整、脑补缺失值。
- 无数据支撑的段落一律省略，不写「示例数据」占位。
- 数字格式化（千分位、百分比、单位）遵循 `echarts-charting-rules.md`，保持一致。
