# 数据报告信息结构

一份数据报告按固定的 8 段信息结构组织。每段标注**必需**还是**按需**，并说明轻报告 / 完整报告如何取舍。每段对应 `build_report` 工具的一个参数字段（见 SKILL.md）。无数据的段落不传对应字段即自动省略。

## 分级速查
- **轻报告**（单体 data agent「出个报告」）：报告头 + 执行摘要 + KPI 卡片行 + 1-2 张图表 + 口径与数据来源声明。其余段省略。
- **完整报告**（专家团 finalization）：全部 8 段。

---

## 1. 报告头（必需）
- 内容：报告标题、分析主题一句话、**数据截至时间**、生成时间、数据来源系统。
- 对应字段：`title` / `subtitle` / `meta{data_as_of, generated_at, source}`。
- 省略规则：不可省略。数据截至时间是可信度的一部分，必须出现。

## 2. 执行摘要（必需）
- 内容：一句话结论 + 2-3 条关键发现，直接给结论/数字，供决策者快读。放最重要的发现和一句话建议。
- 对应字段：`summary`（要点字符串数组）。
- 省略规则：不可省略。轻报告也要有。

## 3. KPI 卡片行（必需）
- 内容：核心指标当前值 + 环比/同比变化 + 趋势方向。每个卡片一个指标。
- 对应字段：`kpis`（[{name, value, delta_pct, delta_dir}]）。
- 省略规则：无核心指标可展示时省略；轻报告保留。

## 4. 图表区（按需）
- 内容：把关键数据画成图表（趋势折线、分类对比柱状、占比饼图等）。服务端用 echarts 渲染，自带 hover tooltip 与 legend 交互。
- 对应字段：`charts`（[{type, title, x, series, caption}]，只传数据，服务端渲染 echarts）。
- 省略规则：轻报告 1-2 张即可；无适合可视化的数据时省略。

## 5. 数据明细表（按需）
- 内容：支撑结论的明细数据表，行列清晰，数字右对齐、格式化。
- 对应字段：`table`（{columns, numeric, rows, note}）。
- 省略规则：轻报告通常省略；数据量过大时只放 Top N 并注明。

## 6. 归因与洞察（按需）
- 内容：解释「为什么」——变化的驱动因素、异常点分析。必须区分 事实 / 推断 / 建议（见 `credibility-rules.md`）。
- 对应字段：`insights`（[{kind, text}]，kind 取 fact/inference/recommendation）。
- 省略规则：轻报告可省略或压缩为执行摘要里的一两句；完整报告必需。

## 7. 口径与数据来源声明（必需）
- 内容：每个核心指标的口径定义（注册口径 vs ⚠️ 自定义口径）、数据来源表、数据截至时间、查询范围与过滤条件。
- 对应字段：`caliber`（[{metric, desc, custom}]；自定义口径设 custom:true）。
- 省略规则：不可省略。这是报告可信的底座，轻报告也要有。

## 8. 风险与待确认（按需）
- 内容：数据质量问题、口径存疑处、样本局限、需业务方确认的假设。
- 对应字段：`caveats`（字符串数组）。
- 省略规则：无已知风险时省略；涉及自定义口径或数据缺口时必须写。
