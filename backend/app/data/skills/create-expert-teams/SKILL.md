# Create Expert Teams

你负责把用户的自然语言需求转换成 Codata 可执行的专家团配置。

## 使用时机

当用户表达以下意图时使用本技能：
- “帮我创建一个专家团”
- “根据这个业务流程生成专家团”
- “把这个任务做成多 agent 团队”
- “设计一个可复用的专家团模板”
- “保存一个专家团用于后续召唤”

## 工作流

1. 明确专家团要解决的问题、输入材料、最终交付物和是否需要改文件/运行命令。
2. 优先使用 `create_expert_teams` 工具，通过 `prompt` 生成专家团草稿。
3. 如果用户要求直接保存，设置 `save: true`；否则先生成草稿并展示关键设计。
4. 若用户给出了完整 JSON 配置，使用 `team` 参数调用工具做强校验，再按需要保存。
5. 工具返回后，向用户说明：
   - 专家成员及职责
   - 任务流程和依赖关系
   - 预计 token 消耗等级
   - 是否已保存，以及专家团 ID

## 调用示例

```json
{
  "prompt": "创建一个 SaaS 产品需求评审专家团，需要产品经理、架构师、测试专家和商业分析专家共同评审 PRD，输出风险和实施计划。",
  "category": "技术工程",
  "save": false
}
```

直接保存：

```json
{
  "prompt": "创建一个公众号选题策划专家团，包含趋势研究、内容策划、标题优化和编辑审校。",
  "category": "内容创作",
  "save": true
}
```

## 设计规则

- 成员数量通常控制在 2-5 个，避免无意义扩大 token 消耗。
- 每个成员必须有清晰职责，任务必须有明确 `expected_output`。
- 任务依赖必须显式表达，后续任务只能引用上游任务的 `output` 变量。
- 大段上下文传递优先使用 `summary` 或 `auto`，减少 token 浪费。
- 除非用户明确要修改文件或执行命令，成员工具不要包含 `write`、`edit`、`bash`。
- 专家团必须能直接在 Codata 专家团页看到并召唤。
